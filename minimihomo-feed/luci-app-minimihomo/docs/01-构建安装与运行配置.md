# MiniMihomo 构建、安装与运行配置

## 交叉编译

SDK 目标为 `qualcommax/ipq807x`、`aarch64_cortex-a53`、musl。正常的构建命令是：

```sh
make package/luci-app-minimihomo/compile V=s
```

本次 r16 的常规依赖链在 SDK 内的 `lucihttp` 阶段停止，原因是 SDK 缺失 `lua.h`，不是插件源码错误。MiniMihomo 是纯 LuCI 资源包，不包含路由器本机二进制；因此使用 SDK 的 `ipkg-build` 对已验证的资源目录打包，生成 `all` 架构 IPK，并验证包内版本与生成器内容。

## 安装 r16

软件包位于：

```text
SDK/bin/packages/aarch64_cortex-a53/minimihomo/luci-app-minimihomo_2.0.0-r16_all.ipk
```

安装后，在路由器执行：

```sh
/etc/init.d/minimihomo enable
/etc/init.d/minimihomo restart
tail -n 100 /tmp/minimihomo.log
```

包升级不会覆盖 `/etc/config/minimihomo`，因为它是 conffile。订阅生成模式需在升级后重新应用订阅或重启服务，才会重新写出 `runtime.yaml`。

## 生成模式启动链路

```text
LuCI 订阅页保存
  ↓
/etc/config/minimihomo
  ↓
/usr/libexec/minimihomo/generate
  ↓
/etc/minimihomo/runtime.yaml
  ↓
procd → /usr/bin/mihomo -d /etc/minimihomo -f runtime.yaml
```

生成器会建立 `proxy-providers`、策略组和规则。URL 非空是订阅生效的唯一前提；URL 的首尾空格会自动去除。

## 导入模式启动链路

```text
LuCI 上传完整 YAML
  ↓
/tmp/minimihomo-draft.yaml
  ↓ 原样替换
/etc/minimihomo/runtime.yaml
  ↓
procd → mihomo
```

插件不再调用 `mihomo -t`，也不修改 YAML。若启动失败，由用户使用以下命令手工定位：

```sh
mihomo -t -d /etc/minimihomo -f /etc/minimihomo/runtime.yaml
tail -n 100 /tmp/minimihomo.log
```

## 重点排错

```sh
uci get minimihomo.global.enabled
uci show minimihomo
/etc/init.d/minimihomo restart
tail -n 100 /tmp/minimihomo.log
```

完整 YAML 中 `rules:` 必须在最左侧顶级；不可缩进到 `proxy-groups` 的最后一组。订阅 URL 需无额外引号、空格或 Markdown 链接格式。
