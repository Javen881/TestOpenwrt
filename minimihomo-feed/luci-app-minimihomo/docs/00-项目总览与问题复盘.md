# MiniMihomo 项目总览与问题复盘

## 目标与边界

MiniMihomo 是 OpenWrt 上的轻量 LuCI 管理界面：由 `mihomo` 内核运行代理，插件负责订阅、运行配置、服务控制、日志与 Controller API 的页面入口。源码保存在本地，后续 Git 操作由维护者手动完成。

插件支持两种互不混写的路径：

1. **订阅生成模式**：LuCI 保存 UCI 选项，启动时自动生成运行 YAML。
2. **完整 YAML 导入模式**：直接使用用户导入的 YAML，插件不对它做校验、矫正或重排。

## 已解决的问题

| 现象 | 原因 | 当前处理 |
| --- | --- | --- |
| 服务生成阶段因 `IPKG_INSTROOT` 退出 | 脚本在运行时采用了安装阶段变量的严格引用 | 移除该不安全用法 |
| 大 YAML 点击应用没有反应 | RPC 文本写入受大小限制/被中止 | 改用 LuCI 文件上传接口，临时保存后原样应用 |
| 导入后可运行，插件“校正”后反而不能运行 | 插件改写了原 YAML 的有效内容或层级 | 不再校验和校正，失败时只保留日志供人工修复 |
| 订阅提示没有可用 URL | UCI 区段类型或 `enabled` 表示不一致 | 对所有区段检查非空 URL，并去除首尾空格 |
| `rules` 被写进最后一个节点组 | YAML 顶级层级未明确结束 | 生成器显式输出顶级 `rules:` |
| 日志可能占用存储 | 长期落盘会消耗闪存 | 日志仅写 `/tmp`，并按行数截断 |
| 节点页消耗资源 | 实时速率采样和自动测速会持续请求 | 已去掉实时采样与自动节点测速，保留手动测试 |

## 当前 Controller 策略

订阅生成模式绑定到路由器 LAN 地址：

```yaml
external-controller: 192.168.10.3:9090
secret: ""
```

同一局域网中能够访问该路由器地址的设备可以无密码调用 Controller。不要将端口 9090 加入 WAN 放行规则，也不要改为 `0.0.0.0`。完整 YAML 导入模式不受此设置影响，必须由用户在 YAML 内自行设置。
